# Сайт Юлии Валишиной

Статический сайт на Astro: главная, обо мне, контакты, индивидуальный коучинг, журнал и две статьи. Вёрстка по `yuliya-valishina.pen`, адаптивные страницы и React-острова для меню, фильтров, FAQ, диалогов и формы.

Стек: Astro, React, TypeScript, Tailwind CSS 4, оригинальные shadcn/ui на Base UI, TanStack Query и Orval. Структура FSD повторяет подход `react-starter`. Цвета макета назначены стандартным переменным shadcn без отдельного слоя темы.

## Локальный запуск

Нужны Node.js **24.18.0** и pnpm **11.15.1**.

```sh
pnpm install
pnpm dev --port 4321
```

Откройте [сайт](http://127.0.0.1:4321/). Astro запускает dev-сервер в фоне. Остановка и логи:

```sh
pnpm exec astro dev status
pnpm exec astro dev logs
pnpm exec astro dev stop
```

## Сборка и проверка

```sh
pnpm check
pnpm preview --port 4322
```

`pnpm check` проверяет воспроизводимость генерации API, форматирование, контракты моковых запросов, типы и статическую сборку. Результат сборки — `dist/`; Node-сервер для размещения сайта не нужен. `pnpm design:check` отдельно проверяет сохранённый графический прототип.

SEO редактируется в `/admin/seo`: общие настройки, основной HTTPS-домен,
заголовки и описания шести страниц, превью ссылок и индексация. У каждой статьи
есть отдельный блок «SEO статьи». Пустые поля статьи наследуют её заголовок,
описание и обложку. Данные сохраняются через `/v1/admin/seo`; публичный контракт —
`/v1/seo`. Сохранение ставит обновление статического сайта в очередь публикации.
В локальном демо пересборку запускает gateway, как и для остального контента.

HTML содержит SEO, Open Graph, Twitter Card и JSON-LD. `sitemap.xml` включает
основные страницы и опубликованные статьи, кроме отмеченных `noIndex`.
Конфиденциальность и 404 закрыты от индексации по умолчанию. Пока основной домен
не указан, canonical и адрес sitemap в robots не выводятся, sitemap пуст,
а robots и метатеги запрещают индексацию. После выбора домена заполните
«Основной адрес сайта» в SEO и сохраните изменения.

Миграция `20261013090000_site_seo` добавляет отдельное JSON-поле SEO.
`backend` → `pnpm content:seed` заполняет новые SEO-настройки и отсутствующие
SEO-поля существующих статей, сохраняя остальной контент и уже отредактированное SEO.

## Показ заказчику через туннель

После первого `pnpm --dir backend setup:local` запустите:

```sh
pnpm demo:tunnel
```

Команда собирает админку и backend, запускает локальные PostgreSQL/Redis и
выдаёт один HTTPS-адрес Microsoft Dev Tunnels (`*.devtunnels.ms`) через встроенный
клиент VS Code. На Mac требуется установленный VS Code. Перед первым запуском
выполните вход GitHub и подтвердите выданный код на странице входа:

```sh
"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code-tunnel" \
  --cli-data-dir .demo/vscode tunnel user login --provider github
```

Токен обычного GitHub CLI для этого сервиса не подходит. Состояние входа и
туннеля хранится в игнорируемом `.demo/vscode`; публикуется только порт `8787`.
Удалённый доступ к редактору и файлам не включается. Для другой установки клиента
можно задать `DEMO_VSCODE_CLI`.
Сайт доступен в корне,
админка — на `/admin/`, API — на `/v1/`. Данные для входа находятся в
`backend/.admin-credentials.json`; их нужно передать заказчику отдельно.
Текущая ссылка также записывается в игнорируемый `.demo/session.json`.
Для локальной проверки той же схемы без туннеля используйте
`pnpm demo:tunnel --local` и адрес `http://127.0.0.1:8787/`.

Сайт использует настоящий API и отдаёт собранную версию без сервера разработки.
После сохранения контента в админке демо автоматически пересобирается;
через несколько секунд обновите страницу сайта. При ошибке остаётся предыдущая сборка.
Заявки сохраняются в существующей локальной базе и видны в админке.
Telegram-уведомления используют настройки `backend/.env`; для проверки без
уведомлений запустите `TELEGRAM_NOTIFICATIONS_MODE=disabled pnpm demo:tunnel`.
Публикация на хостинг в этом демо отключена.
Админка использует HTTPS-cookie, проверку origin и CSRF; Swagger не публикуется.

Оставьте компьютер включённым и с интернетом. На Mac команда удерживает систему
от автоматического перехода в сон, пока работает демо; закрытие крышки всё равно
может остановить доступ. Окно VS Code можно закрыть: туннель работает отдельным процессом.
`Ctrl+C`
останавливает туннель и его серверы, сохраняя базу данных и обычный локальный
сервер сайта. Dev Tunnels сохраняет состояние туннеля между запусками; адрес
проверяется заново при старте. Это временный показ без гарантии доступности сервиса.
Порты `3001`, `4323` и `8787` должны быть свободны. Для рендера на сервере
`API_INTERNAL_BASE_URL` указывает на локальный backend; браузер обращается
к API через HTTPS-адрес туннеля.
Если сервис меняет адрес,
команда останавливает демо; перезапуск обновляет настройки доступа и сборку.
При этом варианте демо все посетители используют общий IP-лимит
заявок (5 отправок за 10 минут).
Для Cloudflare установите `cloudflared` и используйте
`DEMO_TUNNEL_PROVIDER=cloudflare pnpm demo:tunnel` — он выдаёт `*.trycloudflare.com`.
Вариант `DEMO_TUNNEL_PROVIDER=localhost-run pnpm demo:tunnel` использует SSH без
личных ключей, но его бесплатный анонимный адрес может смениться через несколько
минут и остановить демо. Для длительного показа он не подходит.

## Данные и NestJS backend

По умолчанию `PUBLIC_DATA_SOURCE=mock`: страницы получают типизированные данные на этапе сборки, форма и журнал используют сгенерированные Orval-хуки TanStack Query. Моки работают без сети. Форма показывает состояние демонстрации, ничего не отправляет и не сохраняет.

Контракт хранится в `openapi/openapi.json`. Он экспортируется из Swagger работающего NestJS backend в `backend/`. `.env.example` описывает параметры.

```sh
pnpm api:generate
OPENAPI_SPEC_SOURCE=backend/docs/api/public-openapi.json pnpm api:update
```

Orval генерирует клиент, модели и Query/Mutation hooks в `src/shared/api/generated`. Документация [docs/api.md](docs/api.md) строится из того же OpenAPI. Сгенерированные файлы вручную не редактируются.

Для сборки с настоящим API задайте `PUBLIC_DATA_SOURCE=api` и `PUBLIC_API_BASE_URL`. Сервер должен быть доступен при сборке: новые статьи и изменения контента появляются после повторной статической генерации. NestJS backend находится в `backend/`, графическая админка на React Starter — в `admin/`. Текст статей из Tiptap сохраняется в Markdown и превращается в HTML при сборке Astro.

## Бэкенд и NetAngels

Бэкенд на основе `nest-js-starter` сохраняет заявки в PostgreSQL, отправляет
уведомления в Telegram и предоставляет защищённый API редактирования контента.
Вход по email и паролю, регистрация отключена.

Форма защищена без капчи: сервер ограничивает отправки до 5 за 10 минут с
одного IP, игнорирует заполненное скрытое поле `website` и объединяет одинаковые
заявки за 10 минут независимо от IP. Повторы сравниваются по имени, контакту,
тексту и программе после удаления пробелов по краям. Проверка и создание
выполняются в одной транзакции PostgreSQL с блокировкой, поэтому одновременные
отправки не создают повторных уведомлений в Telegram. Ловушка и повторы получают
обычный успешный ответ; при превышении лимита сервер возвращает 429 и
`Retry-After`, а форма сообщает, сколько минут подождать. Эти меры ограничивают
обычный спам, но не исключают отправки разных заявок с разных IP.

```sh
pnpm --dir backend install
pnpm --dir backend setup:local
pnpm --dir backend dev:host
```

Локальный администратор создаётся автоматически, данные для входа — в
`backend/.admin-credentials.json` (не в Git). В режиме API контент берётся
из локального NestJS при сборке и отправка формы сохраняет настоящую заявку.

Чтобы локальный сайт показывал контакты и другие изменения из админки,
создайте `.env` в корне с `PUBLIC_DATA_SOURCE=api` и
`PUBLIC_API_BASE_URL=http://localhost:3000`. Backend должен работать во время
разработки и сборки. Режим `mock` использует отдельные демонстрационные данные
и не получает изменения из админки.

Production рассчитан на управляемый хостинг **NetAngels**. Код выкладывается
кнопкой **Run workflow** в GitHub Actions. После изменения контента очередь
бэкенда автоматически запускает пересборку статического Astro-сайта через 30
секунд без новых правок. Кнопка «Обновить сайт» в админке запускает ту же
очередь сразу для сохранённого контента. Для этого на сервере нужны
`SITE_REBUILD_MODE=enabled`, `GITHUB_REPOSITORY`, `GITHUB_PUBLICATION_REF`,
`GITHUB_ACTIONS_TOKEN` и `PUBLIC_SITE_URL`. Без настройки админка показывает
причину недоступности кнопки. При ошибке остаётся предыдущая версия. Настройка
описана в [backend/docs/netangels.md](backend/docs/netangels.md), API и команды —
в [backend/README.md](backend/README.md).

## Админка

Основа — React Starter с его FSD, Axios, TanStack Query, React Router,
React Hook Form, Zod, Orval, shadcn/Base UI, Tailwind и тестовой инфраструктурой.
Добавлен Tiptap для визуального редактирования статей.

```sh
pnpm --dir admin install
pnpm --dir admin dev
```

Админка доступна на `http://localhost:5173/admin/`; локальный NestJS должен
работать на `localhost:3000`. Разделы: заявки и заметки, статьи, программы,
контакты, главная, FAQ, соцсети и настройки сайта. Статьи и программы можно
сохранять черновиками, публиковать и удалять. Подробности в [admin/README.md](admin/README.md).
На хостинге NestJS отдаёт её по адресу `https://api.example.ru/admin/`;
отдельный сервер для React не нужен.

## Структура

```text
backend/          # NestJS, PostgreSQL, Redis и очереди
admin/            # React Starter, FSD и Tiptap
src/
├── app/          # Astro srcDir: маршруты, layouts, providers, острова, стили
├── pages/        # FSD-композиции страниц
├── widgets/      # Шапка, подвал и секции страниц
├── features/     # Меню, FAQ, диалоги и заявка
├── entities/     # Материалы, услуги, FAQ и настройки сайта
└── shared/       # shadcn/ui, API, изображения, утилиты и маршруты
openapi/          # OpenAPI snapshot
scripts/openapi/  # Импорт контракта, документация, проверка генерации
tests/            # Проверки транспорта и мокового контракта
design/           # Исходные изображения, PNG и ранний графический прототип
yuliya-valishina.pen
```

Подробнее — [docs/architecture.md](docs/architecture.md). Плавающий блок социальных сетей адаптирован из `edge`: закреплён справа внизу, раскрывается при наведении, на мобильном — по нажатию. SVG взяты из ресурсов `edge`. Профили задаются через API админки; незаполненные соцсети скрыты. Если все адреса пустые, виджет не отображается.

## Макет и контент

`.pen` — редактируемый источник дизайна. Его читают и меняют через MCP pen.dev; расположение файла сохраняет пути к `design/assets/`. Растровый прототип сохранён отдельно: `make preview`, `make build` и `make check` относятся к нему.

Исходное задание — [docs/brief.md](docs/brief.md), статусы материалов — [design/README.md](design/README.md). Портрет изображает сгенерированную модель. Реальные фотографии, видеообращение, профили соцсетей, юридические реквизиты и подтверждённые истории клиентов добавляются перед публикацией.
