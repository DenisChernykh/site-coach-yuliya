# Бэкенд сайта Юлии Валишиной

NestJS 11, Prisma 7 и PostgreSQL. Основа — локальный `nest-js-starter`,
точный исходный commit указан в [STARTER.md](STARTER.md). Границы его модулей,
cookie-сессии, Argon2, CSRF, проверка Origin, типизированная конфигурация,
RFC 9457 и lifecycle сохранены.

## Что реализовано

- Публичные данные для существующего Astro-сайта: настройки, контакты, главная,
  программы, статьи, FAQ и социальные сети.
- Приём заявок: валидация, обязательное согласие, ограничение частоты, сохранение
  выбранной программы и её названия на момент заявки.
- Защищённый API админки: список и поиск заявок, статусы, заметки, доставка
  Telegram; редактирование контента, создание и удаление статей и программ,
  черновики и публикация.
- PostgreSQL-очереди уведомлений и пересборки Astro; повторы ошибок, восстановление
  после перезапуска, статус публикации и ручное обновление.
- Единственный заранее созданный администратор. Логин — email, пароль хранится
  как Argon2-хеш. Регистрация отключена.
- Управляемый хостинг NetAngels и ручной GitHub Actions workflow, который также
  автоматически вызывается после редактирования контента.

Графическая админка находится в [../admin/](../admin/README.md). Она основана
на React Starter и использует Tiptap для статей. NestJS отдаёт её готовую
сборку по `/admin/` из каталога `ADMIN_STATIC_DIR`; на NetAngels этот путь
автоматически назначает точка запуска. API и интерфейс работают в одном процессе.

## Локальный запуск

Нужны Node.js **24.18.0**, pnpm **11.15.1** и запущенный Docker Desktop.
Все команды ниже выполняются в `backend/`.

```sh
node --version
pnpm --version
pnpm install
pnpm setup:local
pnpm dev:host
```

`setup:local` запускает отдельный PostgreSQL на `55438`,
применяет миграции, заполняет первоначальный контент и создаёт администратора.
Случайные секреты находятся в `.env`, локальные логин и пароль — в
`.admin-credentials.json` с правами `600`; оба файла исключены из Git.
Начальный контент заполняется один раз: последующие запуски сохраняют правки
и не восстанавливают удалённые статьи.

API: `http://localhost:3000`, Swagger: `/docs`, полный OpenAPI: `/openapi.json`.
Для Astro задать в корневом `.env`:

```dotenv
PUBLIC_DATA_SOURCE=api
PUBLIC_API_BASE_URL=http://localhost:3000
```

Запустить сайт на `http://localhost:4321` — этот origin уже разрешён локальным
`.env.example`. Для `127.0.0.1:4321` добавить соответствующий origin в CORS.
Админку для разработки запускать из `admin/` командой `pnpm dev`, адрес —
`http://localhost:5173/admin/`. Этот origin также разрешён локальной конфигурацией.
Локальные внешние интеграции отключены; заявки сохраняются, уведомления ждут
в PostgreSQL до включения Telegram.

## Авторизация клиента админки

`POST /v1/auth/login` принимает `{ email, password }` и возвращает CSRF-токен,
устанавливая HttpOnly-cookie. Клиент отправляет `credentials: 'include'`.
Для POST/PUT/PATCH/DELETE добавлять JSON Content-Type, разрешённый Origin и
`X-CSRF-Token`. После перезагрузки токен можно получить через
`GET /v1/auth/csrf`; текущий пользователь — `GET /v1/auth/me`, выход —
`POST /v1/auth/logout`.

Публичная форма `POST /v1/consultations` требует разрешённый Origin и JSON,
но не требует входа и токена сессии. За десять минут допускается пять попыток
с одного IP. Сервер сохраняет дату и версию согласия. Ошибки возвращаются
как `application/problem+json`, без исходных отклонённых значений.

## Основные маршруты

| Маршрут                                            | Назначение                                       |
| -------------------------------------------------- | ------------------------------------------------ |
| `POST /v1/consultations`                           | Сохранить заявку и уведомление                   |
| `GET /v1/admin/consultations`                      | Список, `page`, `limit`, `status`, `search`      |
| `GET/PATCH /v1/admin/consultations/{id}`           | Просмотр, статус, заметка                        |
| `POST /v1/admin/consultations/{id}/telegram/retry` | Повтор FAILED-уведомления                        |
| `GET/PUT /v1/admin/site`                           | Настройки сайта                                  |
| `GET/PUT /v1/admin/seo`                            | SEO сайта и страниц в черновике                  |
| `GET /v1/admin/cms`                                | Общий черновик CMS и его версия                  |
| `PUT /v1/admin/cms/draft`                          | Сохранить страницы с проверкой версии            |
| `POST /v1/admin/cms/publish`                       | Опубликовать сохранённый снимок                  |
| `GET /v1/page-layouts`                             | Порядок и видимость опубликованных секций        |
| `GET/PUT /v1/admin/contacts`                       | Email, телефон, Telegram, адрес                  |
| `GET/PUT /v1/admin/home`                           | Главная страница                                 |
| `GET/PUT /v1/admin/faq`                            | FAQ, PUT принимает `{ items: [...] }`            |
| `GET/PUT /v1/admin/social-links`                   | Социальные сети, PUT `{ links: [...] }`          |
| `GET/POST /v1/admin/articles`                      | Статьи, POST `{ content, published, sortOrder }` |
| `PUT/DELETE /v1/admin/articles/{id}`               | Изменение и удаление статьи                      |
| `GET/POST /v1/admin/programs`                      | Программы, такой же формат записи                |
| `PUT/DELETE /v1/admin/programs/{id}`               | Изменение и удаление программы                   |
| `GET /v1/admin/publication`                        | Статус очереди пересборки                        |
| `POST /v1/admin/publication/retry`                 | Пересборка опубликованного контента              |
| `GET /v1/content-version`                          | Версия контента для сборки                       |

Статусы заявок: `NEW`, `IN_PROGRESS`, `COMPLETED`, `ARCHIVED`. Удаление программы
не удаляет старые заявки: название выбранной программы сохранено отдельно.
Сохранение контента меняет только общий черновик CMS. После публикации и
пересборки контакты появляются в подвале сайта; Telegram-контакт также
обновляет ссылку плавающего блока соцсетей. Обложки статей используют
`art`/`landscape`, относительный путь или HTTPS URL; загрузка файлов не добавлена.
`bodyMarkdown` хранит визуально отредактированный текст статьи. Если это поле
отсутствует, сайт использует прежние структурированные разделы; редактор
переносит их в Markdown при первом сохранении.

## Контракты и проверки

```sh
pnpm check:quick
pnpm test:site:e2e
pnpm check
```

`check:quick`: форматирование, Prisma, drift и lint OpenAPI, ESLint, типы,
модульные тесты, границы архитектуры и production-сборка. `test:site:e2e`
использует запущенные `compose.local.yml` зависимости, создаёт временную БД,
поднимает скомпилированный HTTP-сервер и удаляет только эту БД после проверки.
`check` дополнительно запускает интеграционные и e2e-проверки основы в Docker.

`pnpm openapi:generate` создаёт полный контракт `docs/api/openapi.json` и
публичный срез `docs/api/public-openapi.json`. Обновление клиента Astro из корня:

```sh
OPENAPI_SPEC_SOURCE=backend/docs/api/public-openapi.json pnpm api:update
```

## Размещение и публикация контента

[Инструкция NetAngels](docs/netangels.md) описывает тарифы, настройку панели,
переменные GitHub, первый запуск с созданием администратора, автоматическую
пересборку и откат кода. Workflow: `../.github/workflows/deploy-netangels.yml`.
Доступы хостинга, Telegram и GitHub не включены в репозиторий.

[STARTER-README.md](STARTER-README.md) и исходные runbooks сохранены как справка
по основе. Описанные там VPS/Compose+Caddy и дополнительные почтовые/очередные
контуры не являются способом production-размещения этого проекта.

Редактор автоматически создаёт адрес статьи из русского заголовка, разрешает
совпадения суффиксом и сохраняет адрес при переименовании. Идентификатор новой
программы создаётся сервером. Контакты и социальные сети редактируются одной
формой и сохраняются транзакционно через `PUT /v1/admin/contacts` (`links`).
Кнопка «Опубликовать» переносит общий черновик в публичные таблицы и ставит
пересборку в очередь. Кнопка «Обновить сайт» запрашивает немедленную пересборку
уже опубликованного контента через ту же очередь; во время активной сборки
повторный запуск отклоняется. Подробнее: [CMS](../docs/cms.md).

## Медиа

[Общая очередь обработки, загрузка частями и cron](docs/media.md).
Redis в рабочем API не используется: сессии и ограничения запросов хранятся
в PostgreSQL. Старые Redis/BullMQ-адаптеры основы и их изолированные тесты
остаются справочным кодом и не подключены к графу приложения.
