# Устройство проекта

## Сайт и FSD

Astro генерирует HTML статически (`output: static`). `srcDir` направлен на `src/app`: только `src/app/pages` содержит файловые маршруты. `src/pages` — обычный FSD-слой композиций, его файлы не превращаются в дополнительные URL.

Зависимости направлены вниз: `app → pages → widgets → features → entities → shared`. Каждый слайс экспортирует публичный API через `index.ts`. Внутренние файлы другого слайса не импортируются. В `shared/ui` лежат исходные компоненты shadcn, без обёрток, переименованных вариантов и дополнительного слоя темы.

`src/app/styles/index.css` назначает цвета макета стандартным токенам `background`, `foreground`, `primary`, `secondary`, `accent`, `muted`, `border`, `input` и остальным переменным shadcn. Шрифты Manrope и Cormorant Garamond поставляются локально.

## Маршруты и интерактивность

| URL                           | Содержимое                                 |
| ----------------------------- | ------------------------------------------ |
| `/`                           | Главная со всеми секциями макета           |
| `/about/`                     | История Юли и её подход к работе           |
| `/contacts/`                  | Контакты, форма знакомства и FAQ           |
| `/coaching/`                  | Индивидуальный коучинг и форматы работы    |
| `/journal/`                   | Журнал с фильтрацией по теме               |
| `/journal/finding-your-work/` | Первая статья                              |
| `/journal/showing-up/`        | Вторая статья                              |
| `/privacy/`                   | Информация о данных демонстрационной формы |

Динамический маршрут статьи использует `getStaticPaths()` и генерирует отдельную HTML-страницу для каждого материала. Изображения обрабатываются Astro в WebP, первый портрет загружается сразу, остальные — лениво.

Верхний уровень Astro загружает данные и передаёт их вниз. React работает только в островах: мобильное меню, FAQ, диалоги, фильтр журнала и заявка. Для формы и журнала `app/islands` оборачивает компоненты в `QueryProvider`; Astro-слоты передают острова в композиции страниц без обратного импорта `app` из нижних слоёв. Каждый провайдер создаёт свой `QueryClient` через `useState`, поэтому кэш не разделяется между серверными рендерами.

Журнал получает `initialData` из статической сборки. В моковом режиме повторный запрос выключен, тема фильтруется локально; после подключения API сгенерированный Query hook обновляет список. Форма использует Orval Mutation hook и показывает ошибки, ожидание, результат и повторное заполнение. Ошибка переводит фокус на первое проблемное поле. Escape закрывает диалоги и меню.

## OpenAPI, Orval и данные

`openapi/openapi.json` — публичный срез Swagger NestJS backend из `backend/docs/api/public-openapi.json`. Orval генерирует:

- DTO в `shared/api/generated/model`;
- функции запросов, Query keys и Query/Mutation hooks с разделением по тегам;
- обращения к одному транспорту `shared/api/client/api-fetch.ts`.

`scripts/openapi/generate-docs.mjs` строит `docs/api.md` из того же контракта. `api:check` повторно генерирует файлы и сравнивает их хеши с исходным состоянием. `api:sync` принимает URL или путь OpenAPI, проверяет документ и заменяет локальный snapshot. Обычная последовательность: `api:sync → api:generate` (`pnpm api:update`).

Транспорт выбирается `PUBLIC_DATA_SOURCE`. По умолчанию он обращается к типизированным фикстурам в `shared/api/mocks`. Запросы GET и POST проходят через те же сгенерированные функции, которые будут обращаться к backend. Ответы копируются, чтобы клиент не менял исходные фикстуры. POST проверяет поля и согласие, возвращает `preview` и не хранит заявку. В режиме `api` транспорт использует `PUBLIC_API_BASE_URL`, `fetch` и `AbortSignal`.

Публичный клиент использует тот же контракт ошибок, что и админка: `ApiProblemError` хранит проверенный Problem Details, `code`, `requestId`, ошибки полей и `retryAfterMs`; `ApiNetworkError` обозначает отсутствие HTTP-ответа; `ApiProtocolError` — нарушение формата ответа. Допустимые коды берутся из сгенерированного Orval enum, а статус тела сверяется с HTTP-статусом. `Retry-After` принимается в секундах или как HTTP-дата. Моки возвращают те же классы и серверные коды; отмена запроса сохраняет исходную причину отмены. Автоматический повтор GET разрешён один раз для сети и `5xx`, но не для `4xx` и protocol errors; POST автоматически не повторяется.

Выбор пользовательского текста принадлежит `model/errors.ts` соответствующей фичи или виджета, а в админке — также моделям страниц. UI отображает готовое сообщение. Серверные `title` и `detail` публичный сайт не показывает; для неизвестной problem error сообщение содержит `requestId`. Форма заявки округляет серверное время ожидания до минут и не знает о настройках лимитера backend.

Backend реализован в `backend/` на основе `nest-js-starter`; DTO синхронизируются из NestJS Swagger. Для статической генерации API нужен при сборке; контент обновляется пересборкой. Для браузерных запросов backend должен разрешать origin сайта через CORS. Секреты не помещаются в `PUBLIC_*` переменные.

## Рабочая модель макета

Пользователь знакомится с подходом и выбирает знакомство либо формат коучинга. Основные поверхности — главная, коучинг, журнал, статья и форма. Журнал фильтруется по двум темам; подробности историй и видео открываются в диалогах. В mock-режиме форма демонстрационная. В API-режиме заявка сохраняется в PostgreSQL и доставляется в Telegram через очередь. Контакты и тексты редактируются через React-админку; реальные видео, реквизиты и подтверждённые истории требуют материалов владельца.

Формы главной, коучинга и контактов передают `source`: `HOME_CONTACT`, `COACHING_CONTACT` или `CONTACTS_CONTACT`. Источник сохраняется отдельно от выбранной программы; его название отображается в Telegram, списке и карточке заявки в админке. API возвращает `source` и вычисленный `sourceLabel`. Старые заявки и запросы без `source` остаются с `null` и подписью «Источник: Неизвестен». Источник не входит в ключ защиты от дубликатов: повтор одинаковой заявки с другой страницы в течение 10 минут сохраняет первую заявку и её источник.

Плавающий блок соцсетей адаптирован из `panelContacts` локального проекта `edge`: круглые кнопки закреплены справа внизу, в свёрнутом виде перекрываются с шагом 10 px, при наведении раскрываются вверх. На мобильном блок раскрывается по нажатию; закрывается повторным нажатием, нажатием снаружи или Escape. SVG Telegram, VK, RuTube и OK перенесены из ресурсов `edge`, цвета берутся из стандартных переменных shadcn этого сайта. Пока `url` профиля равен `null`, ссылка отключена. Виджет подключён в общем Astro layout для всех страниц.

## Источники дизайна

`yuliya-valishina.pen` — редактируемый источник. Его нельзя менять текстовыми инструментами; используется MCP pen.dev. `design/screens.json` связывает номера 00–09 с ID фреймов и PNG. `design/assets` содержит изображения, которые импортируются в приложение и остаются доступны макету по прежним путям.

`design/prototype/navigation.json` и Python-скрипты обслуживают раннее PNG-превью. Оно сохранено для сравнения, отдельно от сайта Astro. `pnpm design:check` проверяет ресурсы и переходы этого превью. Изменение макета выполняется через MCP, затем экспортируются соответствующие экраны и обновляются манифесты.

## Backend и публикация

NestJS обрабатывает заявки, авторизацию и редактирование контента. PostgreSQL
хранит содержимое сайта и очереди Telegram/публикации; Redis обслуживает сессии
и ограничения частоты. Вход по email и паролю; пользователь создаётся заранее.
Графический интерфейс админки ещё не реализован.

На NetAngels работает один Node.js-сайт для API и отдельный статический сайт
Astro. GitHub Actions собирает проект и выкладывает release со сменой
символьной ссылки. Контент и постановка пересборки изменяются в одной транзакции.
После 30 секунд без правок worker запускает site-only workflow, проверяет его
результат и версию на сайте. Новые изменения во время сборки вызывают следующую
сборку. Документация эксплуатации — `backend/docs/netangels.md`.

## Административный интерфейс

`admin/` скопирован из React Starter с сохранением FSD, библиотек и проверок.
Entities владеют read queries и query keys, features — изменениями,
pages — композицией, app — router и providers. Клиент Axios, React Query hooks
и Zod schemas генерирует Orval из полного OpenAPI `backend/`.

Tiptap сохраняет Markdown в `ArticleDto.bodyMarkdown`. Публичный сайт
преобразует его в HTML при сборке через react-markdown; сырой HTML не исполняется.
Статьи прежнего формата остаются совместимыми до сохранения в редакторе.

CMS хранит общий снимок черновика в `site_cms_drafts`. Административные API
меняют этот снимок; публичные API продолжают читать опубликованные таблицы.
Публикация атомарно переносит сохранённые тексты, SEO, статьи, программы и
раскладку секций в публичные таблицы и ставит пересборку в прежнюю очередь.
Редактор страниц проверяет версию снимка при сохранении и публикации.
Превью использует компоненты Astro через статическую `/cms-preview/` и
передаёт черновик через `postMessage` с проверкой origin. Форма заявки в
превью отключена. Подробнее: [cms.md](cms.md).

Production bundle React входит в релиз NestJS. Один Node.js процесс отдаёт
`/admin/` и `/v1`, а отдельный статический сайт NetAngels — Astro. Очередь
публикации запускает GitHub Actions только для пересборки публичного сайта.
