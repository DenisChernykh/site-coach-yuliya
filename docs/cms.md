# Редактирование сайта

В админке /admin/editor доступны главная, «Обо мне», коучинг, контакты и
журнал. Первый экран закреплён. Остальные секции можно скрывать без удаления
содержимого и перемещать за иконку захвата слева от названия. Для сортировки
используется dnd-kit: мышью — потянуть за ручку, на телефоне — удержать её
и перетащить. С клавиатуры — пробел или Enter на ручке, стрелки вверх/вниз,
пробел или Enter для завершения; Escape отменяет перемещение.
Общие тексты используются на нескольких страницах; редактор отмечает это
рядом с полями.

В меню админки остаются заявки, редактор сайта, статьи, программы и SEO.
Внутри CMS видны вкладки «Страницы», «Настройки сайта» и «Контакты и соцсети».
Настройки и контакты открываются в широкой рабочей области; правки сохраняются
при переключении вкладок и включении предпросмотра. В секции «Способы связи»
есть переход на общую вкладку контактов. FAQ редактируется в секции
«Частые вопросы». Отдельные прежние формы удалены. Их адреса
перенаправляют в нужную панель редактора: /admin/contacts и /admin/socials
открывают контакты, /admin/home — главную, /admin/faq — FAQ,
/admin/site — настройки сайта.

Меню хранится во вкладке «Настройки сайта». «Обо мне», «Коучинг», «Журнал»
и «Контакты» ведут на `/about/`, `/coaching/`, `/journal/` и `/contacts/`.
«Подход» ведёт к секции главной по `/#approach`. Под каждым адресом указано,
страница это или секция. Сайт и превью используют сохранённое меню без
скрытой подмены адресов. Миграция исправляет прежний `/#about` и переносит
автоматически добавлявшийся пункт «Контакты» в данные меню; остальные ссылки,
названия и неопубликованные правки сохраняются.

Превью использует существующие Astro-компоненты сайта, их стили, карточки,
FAQ и Markdown-рендерер статей. Статическая /cms-preview/ содержит только
демонстрационные данные. Текущий черновик передаётся из авторизованной
админки через postMessage с проверкой origin и окна-источника.
Черновики в browser storage не сохраняются. Форма заявки в превью отключена.
Доступны обычный размер, телефон и отдельный режим предпросмотра.

Статьи по-прежнему редактируются в Tiptap и сохраняют Markdown. У них есть
живое превью в оформлении страницы статьи. Статьи и программы остаются
отдельными разделами; флажок определяет включение материала в следующую
публикацию.

## Сохранение и публикация

1. Изменить поля или порядок секций и проверить превью.
2. Нажать «Сохранить черновик».
3. Нажать «Опубликовать» в редакторе либо «Опубликовать сохранённое»
   в остальных разделах админки.
4. Дождаться успешной пересборки сайта в существующем индикаторе публикации.

Сохранение контента через административные API теперь меняет только черновик.
Публичный API читает прежние таблицы опубликованного контента.
SEO сайта и статей сохраняется в том же черновике и публикуется вместе с ним.
Публикация атомарно переносит сохранённый снимок в эти таблицы и ставит
пересборку в прежнюю очередь. Повтор публикации той же версии не создаёт
дополнительную сборку. Правки, сохранённые после публикации, остаются
черновиком до следующего нажатия кнопки.

Редактор проверяет версию перед сохранением и публикацией. При конфликте
вкладок изменения остаются в форме; можно скопировать их и явно загрузить
свежий черновик. Переход из редактора и закрытие вкладки предупреждают о
несохранённых изменениях.

## Совместимость и запуск

Миграция добавляет site_cms_drafts и необязательный site_content.page_layout.
Исходный контент и адреса статей сохраняются. Первый запрос CMS создаёт
черновик из существующих таблиц без постановки сборки. Пока порядок секций
не опубликован, сайт использует исходный порядок.

Статический хостинг сохраняется; дополнительный сервер рендеринга не нужен.
В сборке админки VITE_CMS_PREVIEW_URL указывает на /cms-preview/ публичного
сайта. Workflow NetAngels получает этот адрес из PUBLIC_SITE_URL.
Origin сайта должен входить в CORS_ORIGINS backend: тот же список используется
для разрешённых iframe в CSP админки. PUBLIC_API_BASE_URL публичного сайта
задаёт разрешённый origin админки; при другом адресе можно задать
PUBLIC_CMS_ADMIN_ORIGIN. Локальные localhost-origin разрешены для разработки.

После выкладки backend с миграцией нужно собрать и выложить сайт, чтобы
статическая страница превью была доступна. Откат к старому коду возвращает
прежнее поведение административных API. Миграцию при откате удалять не требуется.

Проверки: pnpm check в корне и admin/, pnpm check:quick в backend/,
затем node scripts/check-site-e2e.mjs из backend с локальными PostgreSQL/Redis.
Сквозной сценарий создаёт и удаляет собственную временную БД, отключает
Telegram и настоящие внешние публикации.
